# Agent CLI capability map

Reviewed against the four complete inventories and the feasibility spike on 2026-10-30; source checks are static, not Windows runtime validation. The companion [design](design.md) defines proposed commands, policy and rollout. `implemented` means enabled in the foundation; `mapped` means a decided service-backed design, not an implemented CLI. `needs-refactor` means the named view-model/coordinator operation must be shared first. `owner-decision` reserves a command disabled until owner approval. `not-applicable` is restricted to pure presentation intents with a stated reason.

One classification rule applies throughout: **Irreversible** deletes or overwrites user data without an app-held recovery copy, consumes nonrefundable quota, publishes/sends user data to a third party, or changes something the app cannot undo. **Yes** changes machine, Steam or account state but can be undone or rebuilt, including executable installs, process stop/restart and removals with a verified restore path. **No** is read-only, including authenticated/network reads, cache refreshes and pure view state. Ordinary queries or credentials used for an already-authorized read do not count as publishing new user data; initial credential provisioning, pairing and sharing do. For mixed providers/conditional paths use the highest possible severity; a plan returns the exact branch classification and recovery evidence. No presumed vault copy or index-only .bak counts as a backup of deleted content. Executable workflows, killing Steam and Hubcap/lua.tools quota consumption are never No. GUI side effects are recorded even when the CLI replaces a shell/clipboard/navigation affordance with a read.

Inventory accounting: 51 + 77 + 57 + 71 = **256 source rows**. Add the **four legacy routes** and **CloseResultsCommand** = 261 ledger entries. Split compound c:R40 (source read versus acquisition) and d:R64 (hide window versus shut down owner) once each = **263 intent fragments before merging**. Merge **113 redundant fragments** into **150 final intents**. Every source reference remains in GUI location; c:R40 and d:R64 appear twice deliberately for their distinct branches. Views/DropZone.xaml OnDrop is verified in code-behind and covered by a:D1/file and a:D2/link intents; MainWindow.xaml RestartSteam_Click is verified and covered by d:R62/c:R46. They add explicit locations, not duplicate rows. A compound control field/reorder, filter-page or transient-dismiss interaction is grouped by user intent, not by generated method name. Inventory provenance: a=add-downloads, b=manage-builds, c=fixes-mode-plugin, d=settings-shell under /data/playground/_cli-inv/.

Counts by Destructive?: No=66, Yes=55, Irreversible=29. CLI status: mapped=70, not-applicable=7, needs-refactor=67, owner-decision=6. IDs are allocated once by resource; future additions append a new ID without renumbering these reviewed IDs.

Read adaptations intentionally prevent view-entry writes: game/source/depot/preset/mode/launch reads never install, reconcile a vault, persist detected mode, rebase launch state or follow FastFetch. Explicit mutation commands preserve these intents. Original GUI preconditions and gates below retain presentation visibility for traceability; headless conditions and stable disabled codes are defined in design.md. Gate B means the original plugin bridge requires active LuaToolsPlugin opt-in, validated CEF store-page context and unchanged selected Steam; it does not gate the independent CLI pipe. Inherited A7/A11/D1 references mean the corresponding a-inventory install policies detailed in those mapped rows, never additional hidden CLI workflows. Source facts and planned corrections are distinguished in the Action, notes and design.
