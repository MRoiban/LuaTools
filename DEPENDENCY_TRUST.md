# Executable dependency trust

The hardened build ships an **empty compiled allowlist** in `DependencyTrustPolicy.cs`. No upstream DLL, executable, archive, or plugin JavaScript is independently approved. Release digests prove consistency with the publisher, not a source/binary security review. They cannot populate this allowlist. User-writable receipts, manifests, cache state and an executable left by an earlier download are not independent approval.

Eight independent Settings switches default to off: executable game fixes, BetterSteamTools, OpenSteamTools, Steam plugin, DepotDownloaderMod, Steamless, SteamAutoCrack and CloudRedirect. Enabling an external dependency explicitly permits unreviewed executable code through a subsequent Install or Run action. The Steam plugin instead installs this fork's bundled source-owned code through its explicit Install action. Toggling only saves consent. It does not download or launch anything, audit the dependency, or add an independently reviewed hash. Turning a switch off blocks app-initiated installs, tool launches and plugin injection, including existing bundles; it does not terminate external programs or uninstall native DLLs. Steam can load previously installed DLLs on subsequent launches while the switch is off.

## Acquisition remains available

User-triggered tool/install operations preserve the original GitHub release metadata and asset-selection contracts. DepotDownloader (`mendy-tools/DepotDownloaderMod`), Steamless (`atom0s/Steamless`) and SteamAutoCrack (`SteamAutoCracks/Steam-auto-crack`) select the first ZIP asset from their original latest-release endpoint. CloudRedirect (`Selectively11/CloudRedirect`) selects `CloudRedirect.exe`; its add-on selects `cloud_redirect.dll`. The Steam plugin now uses this fork's embedded frontend and source-built WinMM wrapper, with no LTSP release or asset acquisition. OpenSteamTools retains `madoiscool/OST-Nightly` release metadata; BetterSteamTools retains its original raw `latest.toml` manifest and versioned release archive.

`DependencyQuarantine` downloads bounded artifacts as hashed-name `.download` files under the hardened AppData dependency-quarantine directory. It validates metadata filenames, the original repository/asset URL, declared size, network response bytes/time and filesystem reparse points. Upstream names never choose a local path. An intact cache receipt avoids a repeated download of the same artifact; a tampered cache is acquired again. Receipt hashes establish cache identity only. Downloading into quarantine alone does not install or execute anything. Acquisition is serialized; each component cache retains at most eight artifacts and reserves at most 512 MiB of artifact data. Status checks and background-update operations do not acquire executable artifacts. SteamAutoCrack retains its throttled metadata-only release probe.

For an enabled tool/plugin workflow and explicit action, `UserAuthorizedDependencies` validates paths and archive bounds, extracts into staging, records the complete file set and hashes, and promotes the bundle before use. Subsequent installs and launches recheck the workflow switch and bundle receipt; unknown, missing or changed files and reparse paths fail. Tool/plugin archive limits include 4,096 entries, 512 MiB aggregate expansion and a 200:1 ratio after a 1 MiB allowance. These checks constrain installation and detect later byte changes; they do not prove publisher authenticity, benign behavior or an independent review. The local receipt is user-writable and cannot defend against arbitrary code already running as the same Windows user. Executable game fixes instead use an immutable validated archive snapshot and recheck their switch before installation; ordinary manifest-package limits and validation remain separate.

`GithubProxy` retains direct-first fallback through the original source-defined integrations: `https://lua.tools/api/gh/` for public GitHub API requests, and `https://ghproxy.net/`, `https://ghfast.top/`, `https://gh.ddlc.top/` for public GitHub downloads/raw content. Requests use bounded central transport. Mirror routes are restricted to their original GitHub origin types. Mirrors see the public repository/artifact being requested. App credentials, cookies and signed or credential-bearing URL queries are never sent to these mirrors. Only the original public GitHub API pagination parameters `page` and `per_page` may accompany an API mirror request. The server's private proxy token, if it uses one, is not an application credential and is not supplied by this client.

## Explicit executable workflows

The eight settings allow the existing executable workflows without pretending that the artifacts are independently trusted. Each workflow is isolated: enabling Steamless does not enable a downloader, unlocker, game fix or plugin. Game-fix manifests remain non-executable data and keep their existing validation; the separate executable fix slot requires its switch. Existing action/error channels report disabled or invalid bundles.

Automatic executable installation, background executable/plugin updates and automatic runtime installation remain disabled. An absent runtime must be installed separately from Microsoft; SteamAutoCrack cannot install it automatically. Custom mode selects user-managed configuration and does not install or run a dependency. Local depot-key resolution, anonymous manifest/depot architecture and supported non-executable data downloads remain intact. HTTPS, destination/redirect/credential, response-bound and filesystem defenses are unchanged by consent; no switch enables the plaintext backend, telemetry, key donation or upstream app updates.

The Steam plugin setting covers its loader/archive and frontend, including external polyfills. Its runtime starts after a successful explicit install, stops when disabled, and never activates at app startup. The local bridge requires an ephemeral per-process token and rejects browser Origin headers. The injector uses exact receipt-verified frontend bytes; its built-in polyfill is application source. CloudRedirect or another external program may change itself after launch: changed files fail this application's next receipt check, but the application cannot constrain an external program's behavior after it starts.

## Review required before approval

Before adding any independent allowlist entry, separately audit the complete pinned source revision, build inputs, transitive dependencies and produced binaries/scripts. Record the reviewer, exact source revision, reproducible build or independent provenance, artifact hashes and scope of findings here. Populate per-file entries (`component/relative-path`) and the reviewed archive (`component/archive.zip`) only after that review. Do not treat a digest obtained from the same release API, download manifest or local consent receipt as independent evidence. The explicit consent path stays distinct from this reviewed-hash policy.

BetterSteamTools/OpenSteamTools now have targeted static source reviews in [audits/README.md](audits/README.md), with significant unresolved findings. Their distributed DLLs have not been independently approved or matched to a reproducible build. Their switches permit explicit installation of unreviewed code; metadata remains untrusted. ZIP size/CRC checks establish format integrity only. Disabling these integrations does not remove native DLLs previously installed by this application, another application or the user; Steam may load those files at its next launch. No claim is made that external dependencies are safe to run.

Controlled tests use in-memory HTTP responses and inert synthetic files in temporary folders to verify original release/asset URLs, direct-failure mirror fallback, hostile metadata/path rejection, cache integrity, default-off denial and explicitly enabled preparation. They do not download real executables, launch external programs or write into a live Steam installation. Test mappings and recorded runs are in [ENDPOINTS.md](ENDPOINTS.md).
