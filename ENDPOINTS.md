## Online-Fix.me patch folders

`OnlineFixMeClient` uses GET on `https://uploads.online-fix.me:2053/uploads/<game>/Fix%20Repair/`
and eligible files in that folder, with `User-Agent: LuaTools-Fixes/0.2`. The escaped game title
(or the one-game folder supplied by the user) is sent in the path. No global or full-game listing
is requested. Matching tries at most three title candidates; 401/403/404 mean no patch folder,
while other errors or a missing autoindex title stop the lookup as unavailable.

A download first fetches a fresh listing, then sends up to four filtered anonymous cookies from
that response and `Referer: <Fix Repair folder URL>` only on the archive GET. This session is
required by the host to download patches; no lua.tools credentials or browser cookies are used.
Cookies are held only for that call, never cached, logged or persisted. Cookie names are limited to
64 ASCII letters/digits/underscore/hyphen, values to 4,096 permitted ASCII characters. Authorization
and apikey headers are prohibited for this purpose. The credential rule permits cookies only on
GET to this exact origin and `/uploads/<one segment>/Fix%20Repair/<file>`.

The outbound policy allows port 2053 only on this host under `/uploads/`, with no query, userinfo
or fragment. Listings have a 1 MiB / 15-second budget, inspect at most 512 double-quoted hrefs,
and cache results for five minutes per folder without cookies. Names are limited to 200 characters;
only single-volume `fix_repair` RAR/ZIP/7z files qualify. Archive transfers have a 256 MiB / five-minute
budget and use the exact name confirmed in the fresh listing, ignoring server-supplied filenames.
Responses and archives remain untrusted; executable-fix consent and validated conversion govern
installation. Live listing fixtures captured on 2026-10-23 exercise parsing without live test requests.

## Release metadata and executable dependency acquisition

All entries are source-derived. GitHub REST requests use GET, no API token in this app, and `GithubProxy`'s compiled User-Agent. The expected JSON release DTO contains `tag_name`, release name, and assets (`name`, `browser_download_url`, optional `digest`). Publisher-provided `digest` is transport integrity information, not independent permission to execute the payload.

Eight independent default-off switches permit subsequent explicit Install/Run actions for executable game fixes, BetterSteamTools, OpenSteamTools, Steam plugin, DepotDownloaderMod, Steamless, SteamAutoCrack and CloudRedirect. Toggling saves consent only. Enabled workflows can install or execute unreviewed code through bounded staging and local bundle-integrity receipts; neither the switch nor a receipt is an independent audit or authenticity proof. Off blocks app-initiated installs, tool launches and injection but does not terminate external programs or uninstall native DLLs. Steam can load previously installed DLLs on later launches while the switch is off. Endpoint, credential, response-bound and path controls remain mandatory; ZIP size/CRC checks are format integrity, not code trust.

## Unresolved contract and execution limits

The original source availability contract is **GET `http://167.235.229.108/check_apis?appid=...` with `User-Agent: secretgoonpoon`**, returning source-name/status JSON. At the user's explicit request this exact metadata endpoint is restored, without enabling any other remote HTTP traffic. Its isolated client accepts GET only, fixed IP/path/query, no credentials, cookies, proxy, request body or redirects; bodies are capped at 64 KiB, with a 10-second body deadline and 20-second request timeout. At most 32 unique source names (bounded ASCII label characters) and `available`/`unavailable`/`unknown` string statuses are accepted, with whole-response validation before publication. Downloads still go to authenticated `https://lua.tools/api/manifest/download`, with escaped source parameters and existing content validation. Hubcap remains independent.

This exception does not secure the server: network observers can see app IDs and alter availability hints. Trusted HTTPS for the same contract is still needed to authenticate those results. A credential-free GET for app 620 returned HTTP 200, 40 bytes, with **Luie** and **Ryuu** both `available`; see [source-availability-http.json](evidence/source-availability-http.json). This is a point-in-time availability claim, not proof a live authenticated download will succeed. `SourceAvailabilityTests` covers the original response, credential/host leakage, redirects, alternate destinations/queries, oversized bodies and invalid/duplicate/markup source data. General HTTP clients continue to reject the endpoint.

Live authentication, Hubcap usage/downloads, signed object transfers and executable/helper execution were not exercised. Controlled session/transfer fixtures do not prove server-side success. Bounds may reject unusually large legitimate payloads or undeclared package formats; additions require specific contract evidence. No upstream DLL/source binary audit or Steam signature verification is claimed. Executable operations default to blocked but can be explicitly authorized per workflow without independent review. Automatic runtime/app installation and updates, background plugin updates, telemetry and donation remain disabled.
