## Findings

### High — native loader and frontend build provenance unavailable

`winmm.dll` is installed beside Steam, paired with the operating system's `winmm.dll` copied as `winmm_real.dll`; Steam consequently loads native dependency code. See [slot definition](../src/LuaToolsGui/Services/PluginInstallerService.cs#L61) and `InstallAsync`'s staging/write path. The installer comment describes the loader as only launching LuaTools, but this is not evidence of actual DLL behavior. The release Lua backend mentions `launch_luatools()` in `steampluginback/src/lib.rs` (`backend/main.lua:46-48`); that path is absent from both LTSP trees and the current LuaTools tracked tree.

No source, pinned compiler/dependencies, reproducible build, signed independent attestation, or source-to-asset comparison was available here. Consequently loader network access, credential access, process creation, hooks, persistence, export forwarding, and update behavior remain **unresolved**. Readable release JavaScript/Lua can be inspected directly, but cannot be connected to reviewed repository/build inputs. Matching release digests only establish consistency with the same publisher. Obtain the full loader/frontend build sources, transitive inputs, build recipe and independent artifact provenance before approval.

### High, conditional — store page scripts inherit authenticated app actions

The [injector](../src/LuaToolsGui/Services/CefInjectorService.cs#L235) reads `window.Millennium._pending` from the ordinary page world, maps its methods to local HTTP actions, and adds the bridge token itself. The [inline polyfill](../src/LuaToolsGui/Services/CefInjectorService.cs#L475) exposes both the queue and `callServerMethod` on `window`. There is no per-action user gesture authentication. Release frontend `public/luatools.js:619-633,769-772,874-895` uses this same interface for add/source/status/remove/restart and other actions.

Any script already executing in an injected Steam store context can enqueue these allowed operations. This requires page script execution (for example compromised allowed page content, another plugin, or a compromised frontend); it is not an arbitrary internet-origin bypass of raw loopback HTTP. Impact includes installed Lua removal, initiating the add/download workflow, Steam restart and app UI actions. The native token and browser-Origin rejection do not isolate mutually untrusted scripts sharing that page. Keep privileged operations gated in trusted app UI or implement a genuinely isolated and narrowly scoped capability channel. This review did not demonstrate a Steam store XSS or arbitrary native execution through these methods.

### Medium — CDP peer identity is not established

Discovery trusts JSON from `http://127.0.0.1:8080/json` and checks the target's claimed HTTPS store URL. [WebSocket validation](../src/LuaToolsGui/Services/CefInjectorService.cs#L351) restricts the socket to `ws://127.0.0.1:8080/devtools/page/<id>`, without authenticating the listening process. A local service that obtains that port can supply matching target metadata and CDP responses, including fabricated pending bridge requests, to trigger mapped actions. The installer's port probe merely distinguishes an array-looking response; it does not verify Steam ownership. This is conditional on a hostile local peer and an activated workflow, not remote network access by itself. The marker intentionally enables Steam debugging; the bridge token on port 6767 does not authenticate port 8080. Actual Steam CDP binding/origin restrictions and runtime exposure were not tested.

### Low — third-party stylesheet network dependency

Release `public/luatools.js:1521-1537` inserts Font Awesome 6.5.1 CSS from cdnjs. It sets a SHA-512 integrity value, anonymous CORS and `no-referrer`. This is a network/style/font dependency, not an observed remote JavaScript loader. SRI constrains the stylesheet; referenced fonts and browser behavior were not independently audited. Vendoring the required assets would remove the dependency and associated network metadata disclosure.

## Traced execution, network and credentials

The fork selects `plugin.zip` and `winmm.dll` from the original latest-release endpoint. [PluginInstallerService](../src/LuaToolsGui/Services/PluginInstallerService.cs#L299) checks workflow consent, stages bounded frontend extraction, records/rechecks complete file receipts, installs the loader, enables the CDP marker, and activates the plugin only after installation. `AutoUpdateAsync` now returns false. [CefInjectorService](../src/LuaToolsGui/Services/CefInjectorService.cs#L75) injects the exact receipt-verified frontend bytes; an unverified external polyfill falls back to application source. These are acquisition/integrity controls, not independent review of executable behavior.

The release frontend delegates operational network/download work through the method bridge. Its observed direct `fetch` is relative theme JSON (`public/luatools.js:1154-1173`); Discord and SteamDB links are handed to `OpenExternalUrl`. Settings are stubbed to an empty schema (`631-649`), while API-key labels occur in bundled translations. No observed frontend path reads Steam cookies/passwords, transmits an API key, loads remote JavaScript, uses `eval`/`new Function`, or implements self-update. Session storage records popup display gates (`3229-3230,3484`). This is bounded static evidence, not proof that all runtime behavior is safe; injected code runs within the authenticated Steam page's authority.

The ZIP also includes a separate Millennium Lua backend. `backend/main.lua:30-43` forwards HTTP requests to port 6767 without a bridge token; `46-69` optionally shell-launches `%LOCALAPPDATA%\LuaTools\current\LuaTools.exe --minimized`; `133-163` copies JS/CSS into Steam's webkit folder and registers them with Millennium. `backend/steam_utils.lua:24-91` reads Steam library/app manifests; `96-103` contains an explorer shell helper, with no call from the inspected backend main. These files were inspected as data and were not executed. The fork's reviewed injection path executes JavaScript through CDP, not this Lua backend. Direct use of this Lua backend against the hardened token-required server should be rejected; do not weaken authentication for compatibility.

[LocalPluginBridgePolicy](../src/LuaToolsGui/Services/LocalPluginBridgePolicy.cs#L14) creates a random 32-byte per-process token, requires exact IPv4 loopback host/port, rejects Origin headers and compares tokens in constant time. [HttpServerService](../src/LuaToolsGui/Services/HttpServerService.cs#L174) applies it before dispatch. The token is added by the native injector rather than embedded in release JS. It protects raw HTTP clients; the page queue remains a separate trust boundary as described above. No app credential, session cookie, or token was sent to an upstream endpoint during this audit.
