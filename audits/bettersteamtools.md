## Findings

### BST-01 — High: default-on donation uses the signed-in Steam account and sends manifest access codes to an external service

`DonateSettings.enabled` defaults to true; its session mint cap defaults to zero/unlimited. Initialization calls `ManifestDonor::Start()` without an application-level consent check. The worker fetches the external wanted list, intersects it with locally owned depots, asks Steam for manifest request codes, then posts `depot:manifest:code` records to `https://manifest.luastools.xyz/manifestcode/submit`. A second path also submits codes captured from actual downloads. These are manifest authorization codes, **not evidence of password or depot decryption-key theft**; nevertheless this is account-backed authorization sharing enabled by default, with ownership information disclosed for matching depots.

Evidence: [defaults, Config.h lines 50–58](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Config/Config.h#L50-L58); [startup, dllmain.cpp lines 97–104](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/dllmain.cpp#L97-L104); [destination and submission, ManifestDonor.cpp lines 31–50 and 115–125](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/SteamMetadata/ManifestDonor.cpp#L115-L125); [ownership filtering and minting, lines 168–258](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/SteamMetadata/ManifestDonor.cpp#L168-L258); [captured-code submission, lines 285–303](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/SteamMetadata/ManifestDonor.cpp#L285-L303).

### BST-02 — High: default-on self-update replaces the approved DLL using mutable publisher/mirror metadata

The build option `OST_ENABLE_UPDATER` and runtime `updateEnabled` default to on. Startup fetches a mutable pointer, treats any differing version as an update, downloads the DLL, verifies its hash against that same pointer, renames the running DLL to `.old`, and writes the replacement. This happens **before** the restart confirmation; declining restart still leaves the next-launch replacement staged. Hash checking detects transfer mismatch but does not authenticate an independent signer. The pointer and DLL can both come from GitHub raw, jsDelivr, or `git.lua.tools`; a trusted-path replacement affects future Steam launches. A compromised publisher/update mirror capable of supplying both metadata and bytes is inside this trust boundary. This is a source-supported risk, not a claim that an observed update was malicious.

Evidence: [build option, CMakeLists.txt lines 196–208](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/CMakeLists.txt#L196-L208); [runtime default, Config.h lines 80–84](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Config/Config.h#L80-L84); [stage before prompt, dllmain.cpp lines 113–129](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/dllmain.cpp#L113-L129); [pointer/hash and overwrite, AppUpdater.cpp lines 52–146](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Update/AppUpdater.cpp#L52-L146); [mirror chain, Mirror.cpp lines 12–44](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/SteamMetadata/Mirror.cpp#L12-L44). The source supports compiling this out, but that does not prove the downloaded release used that option.

### BST-03 — High: watched Lua files are executable scripts with standard libraries and network helpers

The interpreter calls `luaL_openlibs`, registers GET/POST and ticket-writing helpers, and executes chunks with `luaL_loadstring`/`lua_pcall`. This is not a data-only parser. Startup parses the default Steam `config/stplug-in` directory plus configured paths and watches for changes. A malicious script placed in those directories can execute with Steam's user authority, including standard Lua OS/I/O/package capabilities. This finding does not assert that the local hardened app accepts arbitrary scripts; it establishes the dependency's execution boundary, including files placed by other software or users.

Evidence: [LuaConfig.cpp lines 491–526](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Config/LuaConfig.cpp#L491-L526); [execution, lines 798–844](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Config/LuaConfig.cpp#L798-L844); [startup/watch paths, dllmain.cpp lines 29–34 and 79–85](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/dllmain.cpp#L79-L85).

### BST-04 — High: build inputs are not immutable or fully transport-authenticated; release equivalence remains unproven

Lua 5.5.0 is fetched with `TLS_VERIFY OFF` and no `URL_HASH`. Detours follows mutable `main`; protobuf, spdlog and tomlplusplus use tags rather than exact commit identities. The release workflow uses mutable action tags and `windows-latest`, builds without disabling the updater, publishes the DLL and its self-declared SHA-256 together, and creates a tag/release ZIP. No reproducible-build comparison, independent signature/attestation validation, or archive-to-source equivalence was established in this review. The Lua transport configuration and mutable inputs prevent treating a source commit alone as a complete build-input pin.

Evidence: [Lua.cmake lines 10–16](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/cmake/Lua.cmake#L10-L16); [Detours.cmake lines 10–16](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/cmake/Detours.cmake#L10-L16); [Protobuf.cmake lines 22–29](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/cmake/Protobuf.cmake#L22-L29); [Spdlog.cmake](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/cmake/Spdlog.cmake#L19-L25); [Tomlplusplus.cmake](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/cmake/Tomlplusplus.cmake#L10-L16); [build/publication workflow lines 17–63 and 100–129](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/.github/workflows/main.yml#L17-L63).

### BST-05 — Medium: startup persists a URL handler; redemption writes Steam ticket state before confirmation

Steam startup registers `HKCU\Software\Classes\bst\shell\open\command` to invoke this DLL through `rundll32.exe`. `bst://redeem/...` posts a supplied code to the compiled default `https://luastools.xyz/drm/redeem`, accepts returned app/ticket fields, and writes AppTicket and ETicket values under Steam's per-app registry keys. The subsequent prompt concerns launching the game; the ticket writes have already happened. This is persistent integration and a sensitive state-write surface reachable through a registered protocol; it is not evidence of arbitrary command injection. No Run-key or scheduled-task persistence was identified in the inspected paths.

Evidence: [startup registration, dllmain.cpp lines 102–104](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/dllmain.cpp#L102-L104); [default host and redemption, TokeerBridge.cpp lines 21–22 and 89–139](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Tokeer/TokeerBridge.cpp#L89-L139); [URI dispatch and registration, lines 160–203](https://github.com/madoiscool/BetterSteamTools/blob/4747385bdc7c92fb422e63419a5093566b3bf626/src/Utils/Tokeer/TokeerBridge.cpp#L160-L203).

## Coverage limits and approval requirements

This is a targeted static review of first-party runtime entry points, networking, updater, Lua execution, ticket/registry access, DLL injection, and build/release configuration, supported by repository-wide searches. It is not an exhaustive line-by-line verification of all hook/protocol implementations. No dynamic traffic capture, exploit test, binary reverse engineering, release archive inspection, signature verification, build, reproducibility comparison, or recursive transitive-source audit was performed. Remote services and remotely delivered hook/IPC metadata were not audited. No conclusion of overall safety or absence of hidden behavior is warranted.

Keep the compiled independent allowlist empty for this dependency. Before considering approval, review a complete immutable transitive build, remove insecure Lua fetching, disable executable self-replacement at build time, establish explicit donation consent/default-off behavior, define the Lua and remote-metadata trust boundaries, and independently compare the exact produced DLLs/loaders/archive with the artifacts to be installed. Record independently obtained hashes only after those steps. This report changes no application behavior and approves no artifact.
