## Findings

### High — executable provenance and transitive review are incomplete (approval blocker)

The inspected tree contains no release workflow, package lock file, SDK pin, reproducible-build recipe, or attestation tying the published executable to this commit. The [README build instruction](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/Readme.md#L34-L42) is simply Visual Studio 2022; the [GUI project](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack/SteamAutoCrack.csproj#L3-L33) targets .NET 10. Direct package versions exist, but no complete resolved transitive graph was obtained or reviewed. The [Core project](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/SteamAutoCrack.Core.csproj#L12-L38) references AuthenticodeExaminer, FuzzySharp, IniFile.NET, NinjaNye.SearchExtensions, Serilog, SharpCompress, sqlite-net-pcl/native SQLite, SteamKit2, System.IO.Packaging, System.Security.Cryptography.Xml, ValveKeyValue and in-tree Steamless variants. GUI additionally references Antelcat.I18N.WPF and WPFCustomMessageBox; unpacker projects reference Iced.

Two opaque native `SteamAPICheckBypass` DLLs are checked into the tree and [copied into build output](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/SteamAutoCrack.Core.csproj#L45-L52). Their sources are not in this tree. When the optional bypass mode is enabled, [the tool deploys them beside game executables as `winmm.dll`, `version.dll`, or `winhttp.dll`](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/SteamStubUnpacker.cs#L292-L374), intended to be loaded by the game. The default bypass mode is disabled (same file, lines 63 and 110). These binaries and the bundled Goldberg DLLs remain **unreviewed**, not presumed safe from their names or stated purpose. No malicious behavior is established by this finding.

### High — nested mutable executable download bypasses the host's review boundary

[EMUUpdater](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUUpdater.cs#L16-L29) queries `https://api.github.com/repos/Detanup01/gbe_fork/releases` and selects `emu-win-release-vs26.7z` from the first release returned, without pinning a tag or commit ([selection](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUUpdater.cs#L173-L211)). The returned download URL is used without a source-level host/scheme/redirect allowlist. SHA-256 is checked only when release metadata supplies a nonempty digest ([verification](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUUpdater.cs#L91-L109)); that digest is controlled by the same publishing channel.

The resulting DLLs are later [copied over game Steam API DLLs after moving originals to `.dll.bak`](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUApply.cs#L221-L241). A compromised nested publisher can therefore supply code loaded on the next game launch. The GUI Settings download button explicitly invokes this updater ([lines 64–70](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack/Views/Settings.xaml.cs#L64-L70)); missing emulator files also trigger a download confirmation flow ([lines 479–495](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack/Views/MainWindow.xaml.cs#L479-L495)). No self-update mechanism for the SAC executable was found in reviewed source; the nested emulator updater is distinct.

### Medium — nested transfer/extraction has no explicit resource or reparse bounds

The updater [streams to disk before checking the declared size](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUUpdater.cs#L227-L243). Its 60-second HttpClient timeout does not supply an explicit deadline to the subsequent response-stream copy. No explicit maximum bytes, archive entry count, aggregate expansion, compression ratio, or filesystem reparse checks were found. It [extracts the whole archive using SharpCompress and recursively copies its contents](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUUpdater.cs#L254-L324), validating only the existence of two DLL paths. Malicious release content can exhaust disk or install unnecessary content within the tool directory. SharpCompress internals were not audited; this report does **not** assert a demonstrated archive traversal vulnerability.

### Medium — Restore can delete unrelated files within the selected tree

If any `SteamAPICheckBypass.json` exists anywhere below the selected path, [Restore deletes every matching `version.dll`, `winmm.dll`, and `winhttp.dll` throughout that tree](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/Restore.cs#L14-L58), without per-file provenance. It also [restores every `*.bak` by deleting its unsuffixed counterpart and deletes every `steam_settings` directory recursively](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/Restore.cs#L76-L96). A broad selected folder or unrelated backup files can cause data loss. This is an observed destructive scope issue, not evidence of remote exploitation. Apply and unpack similarly recurse through user-selected game paths; no reparse guard was found in those traversals.

### Low — optional Steam credentials persist in plain configuration

When configuration saving is used, [SaveConfig serializes `EMUGameInfoConfigs` to `config.json` in the application base directory](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Config/Config.cs#L193-L211); that object contains a [Steam Web API key or access token string](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Config/Config.cs#L509-L515). There is no credential-store protection in that path. Official HTTPS Steam API calls use the value in query parameters ([EMUGameInfo lines 166–169 and 234–247](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUGameInfo.cs#L166-L169)). GitHub tokens can be read from manually supplied configuration but are explicitly ignored when writing the Configs property (Config.cs lines 289–293); the updater sends them as Authorization only on its GitHub API request, not as a default header on asset downloads. No host LuaTools credential forwarding or credential harvesting was identified in reviewed source.

## Execution, network and host integration

The reviewed process-launch calls open hyperlinks with shell execution or invoke `explorer.exe` with paths ([MainWindow lines 381, 592, 606](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack/Views/MainWindow.xaml.cs#L381), [About lines 55–60](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack/Views/About.xaml.cs#L55-L60)). No `cmd.exe`, PowerShell command composition, `runas`, requested elevation manifest, service/task persistence, or scheduled updater was found in this pinned tree. This is source-search coverage, not a claim about opaque binary behavior. It inherits the launching user's permissions; game modification does not require that SAC itself launch the game.

Other observed network paths include official Steam Web API/store endpoints, SteamKit anonymous sessions ([LogOnAnonymous](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/Steam3Session.cs#L236-L243)), achievement image URLs with a Steam CDN fallback, and [published-file response URLs fetched into memory](https://github.com/SteamAutoCracks/Steam-auto-crack/blob/f8b93bc2ae76ce3348cc98fd3af8f2b0521c0967/SteamAutoCrack.Core/Utils/EMUGameInfo.cs#L742-L765). The latter and image fetches lack the host's central destination/size policy; no external shell execution of those downloaded metadata files was found.

In this fork, `Services/SteamAutoCrackService.cs` acquires the first latest-release ZIP through DependencyQuarantine, checks existing runtime only, and launches `SteamAutoCrack.exe` with shell execution after consent and receipt validation, working directory set to the bundle directory. No runtime installer is invoked by this service. These controls limit acquisition and future launches, not behavior after process start. The upstream writes `TEMP/`, configuration, logs and nested Goldberg updates next to itself; resulting additions/changes may make the host's subsequent complete-file receipt check fail. LuaTools' quarantine and reviewed-hash policy do not authenticate the nested runtime download or undo game modifications.

## Coverage and required follow-up

Read the trust policy and host service; reviewed upstream updater, apply, restore, configuration, GUI triggers, process orchestration, selected metadata/network paths, project dependencies and bypass deployment; searched the tracked tree for process/elevation/network/loading primitives and build files; enumerated and hashed release content. Steamless parsing code was searched but not exhaustively audited. NuGet transitive packages, Goldberg source/binary equivalence, bypass source/binary equivalence, SQLite data, native libraries, compiler/SDK chain and all release executable internals remain outside verified coverage. No claim of full pinned-source or transitive audit is made.

Before independent allowlisting: pin and audit all nested sources/artifacts and resolved build inputs, produce independent source-to-binary provenance, eliminate mutable optional-digest downloads, add bounded transfers/extraction and filesystem protections, scope Restore to a provenance manifest, and separate mutable application data from verified executable files. Keep all hashes above out of the compiled allowlist until those requirements are met. Do not infer an independent approval from consent, GitHub digests, or this report.
