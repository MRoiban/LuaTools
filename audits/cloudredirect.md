# CloudRedirect dependency source audit

Reviewed 2026-10-15 by Codex (static source review). **Recommendation: keep `CloudRedirect` and `CloudRedirectAddon` unreviewed and default-off; approve no hashes.** This is a bounded audit, not a finding that these binaries are malicious or safe.

- [Release v2.6.6](https://github.com/Selectively11/CloudRedirect/releases/tag/v2.6.6) exposes `CloudRedirect.exe` (9,565,591 bytes) and `cloud_redirect.dll` (1,727,488 bytes), plus publisher checksum files. API digests are publisher consistency claims, not independent provenance. They are deliberately not copied into an approved allowlist.
- Local entry points: `src/LuaToolsGui/Services/CloudRedirectService.cs:30-50` prepares the EXE following explicit consent and launches it with its own working directory; `UnlockerService.cs:627-708` installs the add-on into Steam and toggles configuration. ## Findings

### High — self-update executes new remote bytes without verifying their identity

[AppUpdater.cs:111-152](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/AppUpdater.cs#L111-L152) reads the release checksum only to compare the **existing** executable, then falls back to version comparison. The checksum is not carried into the update result. [AppUpdater.cs:194-275](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/AppUpdater.cs#L194-L275) downloads the metadata-selected URL, checks a 1–50 MiB size and `MZ` prefix, replaces the current executable and launches it. There is no downloaded-file hash or signature verification, independent pin, or explicit repository/asset URL validation in this path. A publisher/release compromise therefore becomes code execution on the user's update action. The UI checks for releases and shows an Update/Skip banner; installation requires its Update button ([MainWindow.xaml.cs:137-190](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/MainWindow.xaml.cs#L137-L190)). This is not evidence of silent automatic installation.

LuaTools' next receipt check can detect the replaced EXE, but cannot prevent that updater's replacement and relaunch inside an already-running dependency. Remediation: remove/disable upstream updating for the bundled tool or require an independently reviewed immutable artifact before replacement and launch.

### Medium — executable helper caches trust pre-existing files

[EmbeddedCli.cs:13-48](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/EmbeddedCli.cs#L13-L48) derives a deterministic temp directory from embedded resources but writes the EXE and DLL only when they do not exist. Subsequent cached returns check only EXE existence. [EmbeddedCloud760.cs:16-50](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/EmbeddedCloud760.cs#L16-L50) has the same behavior, and its directory hash covers only the tool, not `steam_api.dll`. [CliUiCloudProvider.cs:210-247](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/Providers/CliUiCloudProvider.cs#L210-L247) and [Steam760Cloud.cs:50-77](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/Steam760Cloud.cs#L50-L77) execute these files. Preplaced or modified files can therefore replace helpers without matching embedded bytes. This requires write access to the user's temp tree; it is not a demonstrated privilege escalation. Remediation: verify every helper and sidecar against embedded bytes immediately before use, reject redirected paths, and use a private extraction directory.

### Medium, configuration-dependent — cloud storage permits plaintext and disabled TLS validation

[s3_provider.cpp:89-100](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/providers/s3_provider.cpp#L89-L100) accepts a custom HTTP endpoint; [lines 131-136](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/providers/s3_provider.cpp#L131-L136) enables HTTP for that scheme and reads `allow_insecure_http` / `allow_insecure_tls`. [http_transport_win.cpp:144-177](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/http_transport_win.cpp#L144-L177) permits plaintext and can ignore unknown CA, name, date and certificate usage failures. Defaults are secure, but these options expose saves and signed request material to interception when enabled. This behavior is independent of LuaTools' own HTTPS policy. Restrict storage to HTTPS with certificate validation; do not silently inherit these options from imported configuration.

### High trust impact / functional capability — DLL patches Steam and persists through its loader

This is intentional executable behavior, not a separately established exploit. [dllmain.cpp:34-76](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/dllmain.cpp#L34-L76) exposes a SteamTools code-cave entry point and installs packet, manifest, release-state, endpoint and games-played hooks. [cloud_intercept.cpp:4938-4952](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/cloud_intercept.cpp#L4938-L4952) modifies executable memory. [dllmain.cpp:91-103](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/dllmain.cpp#L91-L103) pins the DLL against unloading. Configured parental bypass can also install enforcement patches ([cloud_intercept.cpp:4649-4661](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/cloud_intercept.cpp#L4649-L4661)). An optional manifest endpoint is read from settings and patched into Steam ([cloud_intercept.cpp:4550-4562](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/cloud_intercept.cpp#L4550-L4562)).

The GUI deploys embedded DLL bytes into Steam ([SetupPage.xaml.cs:377-383](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Pages/SetupPage.xaml.cs#L377-L383)) and updates loader configuration ([OpenSteamToolIntegration.cs](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/OpenSteamToolIntegration.cs)). Persistence here is the on-disk DLL plus existing Steam loader, not an observed scheduled task or Windows Run key. Turning off a LuaTools consent switch cannot unload it or constrain Steam's loader. Full approval must include the loader and its exact calling contract.

## Credentials, network and filesystem coverage

- OAuth uses Google/Microsoft authorization and token endpoints, localhost callback listeners, state validation and PKCE ([OAuthService.cs:65-85](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/OAuthService.cs#L65-L85), [lines 186-203](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/OAuthService.cs#L186-L203), [lines 368-383](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/OAuthService.cs#L368-L383)). OneDrive requests `Files.ReadWrite offline_access`; Google uses `drive.file`. Shared client identifiers and client-secret constants are embedded; these are not evidence of a stolen user token. User tokens/keys are handled inside this external process.
- Windows token writes use current-user DPAPI. Legacy plaintext token JSON is accepted and migration is best-effort ([OAuthService.cs:18-56](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/OAuthService.cs#L18-L56), [dpapi_util.h:47-115](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/dpapi_util.h#L47-L115)). DPAPI is protection at rest against other users, not code already running as this user. No credential-exfiltration destination was established in the reviewed paths; this is not a whole-program non-exfiltration proof.
- Expected destinations include GitHub releases, Google Drive, OneDrive, configured S3/R2 hosts, Steam store services and a configured manifest host. The special authenticated cloud download redirect path explicitly removes authorization before following ([http_transport_win.cpp:218-293](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/http_transport_win.cpp#L218-L293)); this does not establish equivalent behavior for every request path.
- The native save HTTP server binds loopback and checks that the source TCP connection belongs to its own Steam process ([http_server.cpp:443-505](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/http_server.cpp#L443-L505), [line 575](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/src/platform/win/http_server.cpp#L575)). Do not describe it as an unrestricted LAN server. Blob paths get canonical containment checks and uploads have limits; race resistance was not proven.
- Writes include temp EXE/DLL helpers, EXE update/`.old` files, Steam-root DLL/log/config, AppData configuration/token data, save caches, metadata and cleanup backups. Cleanup can move saves, edit `remotecache.vdf` and remove empty directories ([CloudCleanup.cs:730-902](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/Services/CloudCleanup.cs#L730-L902)). Atomic write helpers reduce partial writes; they are not a sandbox or authorization boundary.

## Build provenance and missing coverage

**Approval blocker:** source-to-release correspondence is unverified. The source contains CMake C++ DLL/CLI build targets and a .NET 8 WPF project, but no `.github` build workflow was present in this pinned tree. No reproducible build comparison, signing identity verification, CI attestation, complete dependency lock inventory or binary reverse engineering was performed.

[CloudRedirect.csproj:28-30](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/CloudRedirect.csproj#L28-L30) references `System.Security.Cryptography.ProtectedData` 8.0.0 and `WPF-UI` 4.2.0. Their package contents/transitives and the compiler/.NET/runtime inputs were not fetched or reviewed. Native miniz and custom JSON/protobuf/crypto implementations are included in the tree but were not exhaustively audited for memory safety or correctness.

[CloudRedirect.csproj:41-69](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/CloudRedirect.csproj#L41-L69) embeds DLL/CLI files copied from local build output and merely warns when absent, allowing stale resources. [Lines 72-100](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/ui/CloudRedirect.csproj#L72-L100) optionally embed `ui/native/cloud760_tool.exe` and `ui/native/steam_api.dll`. **The `ui/native` files, Steam API DLL source/build provenance and release-build script are missing from this source snapshot**; [.gitignore](https://github.com/Selectively11/CloudRedirect/blob/00969da863c8d7b2e2821ebc2c6cb231bbe56ef2/.gitignore) excludes `ui/native/` and `build.ps1`. C++ `cloud760_tool.cpp` source exists, but that alone does not identify the embedded helper bytes. The external SteamTools/OpenSteamTool loader implementation is also outside this audit.

Coverage prioritized Windows execution/update/extraction, hook entry points, cloud transport and token storage, deployment/cleanup writes and build declarations. Linux/Flatpak, all provider operations, complete save migration correctness, parsing fuzzing, all UI event paths and live Steam behavior were not fully reviewed. No negative search establishes absence of hidden behavior in the release binaries. Before approval, obtain missing build inputs and embedded DLL provenance, fix the update/cache issues, audit all transitives and loader code, then independently reproduce and compare exact artifact bytes. Keep consent distinct from that approval.
