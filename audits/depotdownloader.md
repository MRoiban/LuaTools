# DepotDownloaderMod source and provenance audit

Review date: 2026-10-15. Reviewer: Codex static review. Decision: **do not independently approve the publisher archive or any executable hash**. The source has a high-severity manifest-to-filesystem boundary issue, and the publisher binary has not been independently tied to this source by a reproducible build. This is not a malware-free certification.

## Findings

### High — manifest names control write/delete paths without containment

At the pinned upstream source, [`ContentDownloader.cs:739-755`](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L739-L755) loads `-manifestfile` and makes it the new manifest. Its filenames then feed `Path.Combine(installDir, file.FileName)` and directory creation at [lines 891-917](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L891-L917), staging deletion and file creation/preallocation at [lines 1017-1037](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1017-L1037), and chunk file opens/writes at [lines 1307-1314](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1307-L1314). Old-manifest names also control deletion at [lines 980-987](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L980-L987); that update branch is broader tool functionality, and is not needed for the supplied-manifest creation issue.

SteamKit's [`DepotManifest.cs:131-140`](https://github.com/SteamRE/SteamKit/blob/c31ce16a766c35a0a3a94a6802f13e9bbd2a1281/SteamKit2/SteamKit2/Types/DepotManifest.cs#L131-L140) only changes separators for plaintext filenames; decryption similarly decodes directly at [lines 275-284](https://github.com/SteamRE/SteamKit/blob/c31ce16a766c35a0a3a94a6802f13e9bbd2a1281/SteamKit2/SteamKit2/Types/DepotManifest.cs#L275-L284). Neither path rejects traversal, absolute paths, or Windows path special forms. The parser deserializes a signature section but does not verify its authenticity in [lines 327-386](https://github.com/SteamRE/SteamKit/blob/c31ce16a766c35a0a3a94a6802f13e9bbd2a1281/SteamKit2/SteamKit2/Types/DepotManifest.cs#L327-L386).

Consequently an attacker-controlled, well-formed plaintext manifest can describe an empty file outside the output directory, causing directory/file creation or truncation with the user's permissions before any valid content chunks are necessary. Existing output junctions/symlinks add another escape route. This is a static dataflow finding, not a dynamically demonstrated exploit. Local `ManifestContentPolicy.ValidateRawManifest` (lines 113-144) checks section framing and declared depot/gid; it skips payload entries and does not close this filename boundary. `ManifestFile.Matches` is therefore not authenticity or filename safety verification. The consumer's stdout cleanup containment also does not constrain writes already performed by the child.

Recommendation: reject unsafe decoded filenames and metadata before filesystem access; enforce canonical output and staging containment, Windows reserved/alternate-stream/path rules, and handle-based reparse defenses for every create/open/delete. Validate all entries before any writes. Apply the checks after filename decryption inside the downloader, or run a reviewed patched build with an equivalent complete preflight. Treat manifests as untrusted even when depot/gid match.

### Medium — release build inputs and source-to-binary identity are not independently pinned

The publisher workflow resolves a mutable latest upstream tag and checks it out by tag, uses `actions/checkout@v4`, `actions/setup-dotnet@v4`, `windows-latest`, and SDK `9.0.x`: [workflow lines 36-81](https://github.com/mendy-tools/DepotDownloaderMod/blob/c1b1d909104226dbb8782b6cfb453fe5c9d0b968/.github/workflows/repack.yml#L36-L81). It runs `dotnet publish --self-contained true` with `ContinuousIntegrationBuild=false` at [lines 91-100](https://github.com/mendy-tools/DepotDownloaderMod/blob/c1b1d909104226dbb8782b6cfb453fe5c9d0b968/.github/workflows/repack.yml#L91-L100). Checks establish naming, presence of runtime/license, and ZIP layout, not code identity. Release notes link a tag rather than immutable source SHA [lines 143-162](https://github.com/mendy-tools/DepotDownloaderMod/blob/c1b1d909104226dbb8782b6cfb453fe5c9d0b968/.github/workflows/repack.yml#L143-L162).

Upstream [`DepotDownloaderMod.csproj:23-30`](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/DepotDownloaderMod.csproj#L23-L30) references CsWin32 `0.3.183` (including build/analyzer inputs), protobuf-net `3.2.52`, QRCoder `1.6.0`, and SteamKit2 `3.2.0`. There is no tracked package lockfile or complete transitive package/hash manifest in that revision. [`global.json`](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/global.json#L1-L6) allows SDK roll-forward. Self-contained output additionally carries the .NET runtime/native host; source review of the C# application does not audit those binaries. Deterministic compilation enabled in the project alone does not supply reproducibility of this complete release ZIP.

Recommendation: pin immutable source/actions/SDK/runtime and complete restored package hashes, retain authenticated build provenance and per-file artifact hashes, review transitive build/runtime inputs, then independently rebuild/compare before considering approval. Metadata consistency and user consent cannot substitute for those steps.

### Medium — untrusted manifest resource demands are not bounded by decoded content

Manifest `file.TotalSize` reaches `SetLength` ([lines 1027-1037](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1027-L1037)), and chunk `UncompressedLength` reaches pooled allocation ([lines 1216-1219](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1216-L1219)). Entries, file totals, offsets and chunk sizes lack an application-level aggregate policy here. Local input byte bounds (64 MiB) and free-space checks against declared metadata do not establish that the sum of payload file sizes agrees with that metadata. A malicious compact manifest can exhaust disk or memory after launch. The standalone network-manifest path also inflates and parses CDN ZIP content without an explicit decompressed aggregate limit in [SteamKit Client.cs:137-148](https://github.com/SteamRE/SteamKit/blob/c31ce16a766c35a0a3a94a6802f13e9bbd2a1281/SteamKit2/SteamKit2/Steam/CDN/Client.cs#L137-L148); supplied local manifests are the consumer path reviewed here.

Recommendation: bound file/entry/chunk counts, individual and aggregate sizes, decompression, allocation, offsets, and expansion before preallocation; derive the budget from validated payload entries rather than metadata alone.

## Credentials, networking, and execution trace

The local integration passes app/depot/manifest IDs, a temporary `depotID;hexKey` file, manifest path, output directory and concurrency; optional `-validate` controls resume. It supplies no username, password, QR, remember-password or debug flags (`DepotDownloaderService.cs:346-373`). `ArgumentList` avoids shell interpolation, `UseShellExecute=false` launches the tool directly, and receipt/workflow checks happen just before launch. This gates launch but does not sandbox the child's filesystem/network access.

Upstream parses depot keys into memory ([Program.cs:150-168](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/Program.cs#L150-L168), [DepotKeyStore.cs:14-34](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/DepotKeyStore.cs#L14-L34)) and uses them for local manifest/chunk decryption ([ContentDownloader.cs:587-601](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L587-L601), [lines 1241-1248](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1241-L1248)). No explicit key donation/upload destination was found in this C# path. Malformed key syntax may include the complete input line in an error (`DepotKeyStore.cs:22`); avoid feeding unvalidated secret-bearing lines. Local key files are plaintext under inherited user permissions, deleted best-effort by the job's finally block; crashes and same-user access remain relevant. The tool receives all keys in the dictionary written by the integration, not just the currently selected depot's key.

Without a username/QR flag, [`Steam3Session.cs:440-443`](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/Steam3Session.cs#L440-L443) logs on anonymously. General-purpose credential and QR branches do exist: refresh tokens/Guard data are persisted in deflate/protobuf isolated storage without application encryption ([AccountSettingsStore.cs:24-28 and 74-83](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/AccountSettingsStore.cs#L24-L83)); this persistence is not activated by LuaTools' arguments. The settings file is nevertheless loaded at startup ([Program.cs:48](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/Program.cs#L48)).

SteamKit supplies Steam connection/authentication behavior. CDN endpoints and optional proxy come from Steam's server list ([CDNClientPool.cs:32-43](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/CDNClientPool.cs#L32-L43)); depot keys are passed to SteamKit for decryption rather than placed in the visible CDN call's URL. CDN auth tokens are passed for the selected depot/host. SteamKit's URL builder supports both HTTP and HTTPS according to server/proxy protocol ([Client.cs:330-350](https://github.com/SteamRE/SteamKit/blob/c31ce16a766c35a0a3a94a6802f13e9bbd2a1281/SteamKit2/SteamKit2/Steam/CDN/Client.cs#L330-L350)); therefore the parent's HTTPS policy does not imply an HTTPS-only child. The tool HTTP factory sets IPv4 connection behavior and a User-Agent, using the standard handler without explicit redirect/egress restrictions ([HttpClientFactory.cs:17-27](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/HttpClientFactory.cs#L17-L27)). Exact negotiated endpoints/protocols were not observed.

No application self-updater or subprocess execution API was found in the reviewed C# sources. Downloaded content is written, and executable flags may be set, but it is not automatically launched by this source ([ContentDownloader.cs:1180-1187](https://github.com/SteamAutoCracks/DepotDownloaderMod/blob/906a40987751e0c3425b27f5fadf049acdb89e0e/DepotDownloader/ContentDownloader.cs#L1180-L1187)). The publisher CI performs automatic release rebuilds; LuaTools' explicit acquisition remains a separate operation. The upstream `Scripts/` Python helper has additional third-party data/mirror endpoints, but is outside the C# project/publish path; it was inventoried, not fully audited or executed.

## Limits and approval recommendation

Coverage was the publisher workflow, upstream C# project/source security-sensitive dataflows, consumer handoff, and targeted SteamKit manifest/CDN source. There was no dynamic network capture, adversarial manifest execution, binary disassembly/signature validation, independent rebuild, CI-run attestation verification, exhaustive transitive dependency/vulnerability audit, or complete Python-helper review. No claim is made that the observed release binary equals the reviewed tree or that all unsafe behavior was found.

Keep the compiled allowlist empty for this dependency. Explicit user consent remains consent to run unreviewed code with user privileges. Resolve filename/resource boundaries, review and pin the entire build closure, and establish independently verified artifact provenance before proposing any per-file/archive approval.
