## Findings

### OST-01 — High: build downloads Lua with certificate verification disabled and no content hash

At the pinned source revision, [src/cmake/Lua.cmake:10–16](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/Lua.cmake#L10-L16) fetches `https://www.lua.org/ftp/lua-5.5.0.tar.gz`, explicitly sets `TLS_VERIFY OFF`, and supplies no `URL_HASH`. Its C sources become the statically linked Lua library. A substituted download can therefore become native code inside Steam despite a pinned OpenSteamTool commit. Enable certificate verification, pin an independently verified archive digest, and establish the exact input used in the published build before approval.

### OST-02 — High: mutable build inputs prevent a complete pinned-source claim

[src/cmake/Detours.cmake:10–21](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/Detours.cmake#L10-L21) fetches Microsoft Detours using `GIT_TAG main`; the reviewed application revision does not identify the Detours revision compiled into a release. Additional dependencies use version tags, not immutable commit IDs: [protobuf v3.15.3](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/Protobuf.cmake#L22-L35), [tomlplusplus v3.4.0](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/Tomlplusplus.cmake#L10-L17), and [spdlog v1.17.0 including bundled fmt](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/Spdlog.cmake#L11-L26). [FetchCache.cmake](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/cmake/FetchCache.cmake#L29-L61) can reuse preexisting dependency source trees and disconnect updates. Transitive source contents were not fetched or reviewed in this pass. Pin and audit all resolved inputs, including bundled dependencies and generated-code tools.

### OST-03 — High: installed Lua files execute with full user privileges inside Steam

[src/Utils/Config/LuaConfig.cpp:422–453](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/LuaConfig.cpp#L422-L453) calls `luaL_openlibs`, leaving the standard libraries available, and exposes arbitrary HTTP GET/POST helpers. [ParseFile:700–750](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/LuaConfig.cpp#L700-L750) compiles and executes input using `luaL_loadstring` and `lua_pcall`. There is no sandbox or instruction budget in this path. Lua's standard OS/IO/package facilities imply command execution, filesystem access and native module loading if a script invokes them; this implication was not dynamically tested.

[src/dllmain.cpp:65–77](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/dllmain.cpp#L65-L77) parses configured directories plus `Steam/config/lua` at initialization and starts file watchers; [LuaFileWatcher.cpp:102–116](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/LuaFileWatcher.cpp#L102-L116) reparses changed scripts. Thus a Lua directory is an executable-code trust boundary. This does not establish a bypass of this fork's separate download validation, nor prove that any downloaded script is malicious. Approving only the three DLL hashes cannot approve all future script behavior.

### OST-04 — High: mutable remote metadata directs native hook addresses

[RemoteToml.cpp:16–21](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/RemoteToml.cpp#L16-L21) retrieves pattern/IPC TOML from mutable `OpenSteam001/steam-monitor` channels through raw GitHub and jsDelivr. [RemoteToml.cpp:112–179](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/RemoteToml.cpp#L112-L179) accepts the response and caches it, falling back to writable cache contents. The SHA-256 in the filename is the **Steam DLL's** hash, not an authenticated hash of the metadata response. No signature or pinned metadata-content digest is checked here. Configuration can replace the URL template.

[PatternLoader.cpp:235–243](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/PatternLoader.cpp#L235-L243) returns `module + entry.rva` directly without a module-range check in that branch; [HookMacros.h](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Hook/HookMacros.h#L47-L56) uses resolved addresses for detours. [IPCLoader.cpp:82–108](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/IPCLoader.cpp#L82-L108) also consumes remote interface metadata. Compromise of those data sources/cache can alter native interception or crash Steam. Arbitrary code execution from crafted TOML was not demonstrated. Treat this metadata as security-sensitive update input; authenticate and pin it, validate ranges, and include it in approval scope.

### OST-05 — Medium: plaintext optional manifest provider and unrestricted runtime HTTP

[ManifestClient.cpp:51–55](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/ManifestClient.cpp#L51-L55) includes optional `http://gmrc.wudrm.com/manifest/%llu`, permitting network observers to read the requested manifest identifier and alter its response. The default provider is HTTPS `manifest.opensteamtool.com`; another option is HTTPS `manifest.steam.run`. [LuaConfig.cpp:121–149](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/LuaConfig.cpp#L121-L149) allows scripts to choose URL, POST body and request headers.

[OSTPlatform/Windows/Http.cpp](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/OSTPlatform/Windows/Http.cpp#L26-L183) accepts HTTP and HTTPS with WinHTTP default proxy/redirect behavior and no destination allowlist or explicit redirect revalidation. It applies phase timeouts and a response-size break after reading/resizing beyond 256 KiB; this is not a preallocation hard cap or overall deadline. No runtime TLS certificate-validation bypass was found in this helper. This dependency's network policy is independent of the hardened GUI transport; GUI safeguards do not govern requests issued inside Steam.

### OST-06 — High capability / conditional exposure: additional native DLL loading and game injection

[CloudRedirectHost.cpp:53–109](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/CloudRedirect/CloudRedirectHost.cpp#L53-L109) loads a configurable library path (default `Steam/cloud_redirect.dll`) when cloud support is enabled. It does not authenticate that file before loading. [Pipe/Features/Injection/Injection.cpp:31–66](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Pipe/Features/Injection/Injection.cpp#L31-L66) resolves configured absolute/relative library paths and injects into identified game processes when enabled. [RemoteProcess.cpp:220–248](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/OSTPlatform/Windows/RemoteProcess.cpp#L220-L248) allocates remote memory, writes the path and creates a remote LoadLibrary thread. Both features [default off](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/Config.h#L19-L28). These are explicit capabilities, not evidence of malware; configuration and additional DLLs must be reviewed as separate executable inputs. Parent-process and architecture checks are not cryptographic code approval.

### OST-07 — Approval blocker: release-to-source linkage is asserted, not independently verified

The pinned [builder workflow](https://github.com/madoiscool/OST-Nightly/blob/6ca5f0cca26238c4b18f6ee4cd33be716b1d5702/.github/workflows/nightly.yml#L30-L143) resolves upstream main, checks out that full SHA, builds with CMake/MSVC/Ninja, packages exactly the three DLLs, and writes the claimed upstream SHA into release notes. This is useful provenance intent. However, it uses `windows-latest`, mutable `actions/checkout@v4` and `ilammy/msvc-dev-cmd@v1`, and grants `contents: write`; the recipe contains no artifact attestation or independent reproducibility check. GitHub's release uploader and API digest are the same publishing trust domain. The actual Actions run logs, runner image, dependency resolutions, binary imports/signatures, ZIP contents and independently rebuilt outputs were not verified. **No released DLL or archive has been audited or approved by this review.**

## Credentials, persistence and other observations

- [SteamCredentialStore.cpp:16–23,49–111](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/OSTPlatform/Windows/SteamCredentialStore.cpp#L16-L111) reads/writes Steam app ticket, encrypted-ticket and SteamID registry values under `HKCU/Software/Valve/Steam/Apps/<appid>` and reads ActiveProcess account information. These are sensitive Steam artifacts. The reviewed path does not add a protection envelope of its own. No browser password store, Windows Credential Manager scraping, or fixed credential-upload endpoint was identified in the reviewed paths; unrestricted scripts/native modules make a global non-exfiltration claim impossible.
- [Hooks_NetPacket.cpp:166–171](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Hook/Hooks_NetPacket.cpp#L166-L171) logs original/replacement app access tokens at debug level. [Release builds compile logging macros out](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/CMakeLists.txt#L166-L169), so this is a debug-build confidentiality concern, not a demonstrated release log leak.
- [StatsClient.cpp:29–50](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/SteamMetadata/StatsClient.cpp#L29-L50) can request `https://stats.opensteamtool.com/<appid>`; the stats API [defaults enabled](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/Utils/Config/Config.h#L63-L64). The request discloses app interest and ordinary network metadata. The response supplies a SteamID; this path is not evidence of uploading the current user's credentials.
- [dwmapi.cpp:112–125](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/dwmapi/dwmapi.cpp#L112-L125) and [xinput1_4.cpp:130](https://github.com/OpenSteam001/OpenSteamTool/blob/2a08b0bfdc96c9e3f75df20f3f37bc8d8c09ee3a/src/xinput1_4/xinput1_4.cpp#L130) load `OpenSteamTool.dll` by name. Installation in Steam's directory persists DLL loading across Steam starts. Disabling the GUI switch does not unload these modules or remove that persistence. No additional scheduled task, service installation or Run/RunOnce registration was identified by targeted source searches. That is limited negative evidence, not proof of absence across unreviewed transitive code or binaries.
- No self-replacing executable updater was identified in the reviewed product source. Runtime metadata refresh, script hot reload, configurable DLL loading and the publisher's daily nightly workflow remain update surfaces even with a fixed installed DLL hash.

## Coverage, limits and disposition

Read the selected LuaTools acquisition contract, complete nightly workflow, relevant product initialization/loaders, HTTP helper, remote TOML retrieval and pattern resolution, Lua initialization/execution/watchers, manifest/stats clients, credential registry helper, cloud loader, injection path, hook macros and dependency declarations. Targeted searches covered URLs, execution APIs, registry persistence, credential terms and update behavior. This was not an exhaustive line-by-line audit of all hook implementations, parsers, IPC handling or platform code; no memory-safety guarantee is made. No vulnerability exploit, live Steam run or network behavior of fetched code was tested.

Missing evidence includes the exact transitive inputs used for the July build, audit of those inputs, authenticated runtime metadata snapshot, release build logs/attestation and source-to-binary comparison. Source availability resolves the missing-source question but does not resolve these blockers. Keep OpenSteamTools unreviewed and default off under the existing explicit-consent policy. Reconsider independent approval only after addressing the build/network/script trust findings, pinning and reviewing the full input closure, and independently establishing the provenance of every executable and archive actually approved. The separate CloudRedirect artifact requires its own review.
