# Executable workflow settings

Selected design: mockup.html, revision 1 (selected by agent, not user-approved). Inspected at 728 and 360 px. Native implementation reuses SettingsView SettingsCard, SectionHeader, RowDivider and ui:ToggleSwitch, Segoe UI, 13px labels, 14px horizontal/12px vertical row spacing, 8px card radius and existing brushes. Insert after Install behavior, before General. No hint paragraphs, banners, tooltips or explanatory snippets.

Eight independent persisted switches, all false when absent: Executable game fixes, BetterSteamTools, OpenSteamTools, Steam plugin, DepotDownloaderMod, Steamless, SteamAutoCrack, CloudRedirect. Toggling only stores consent; no download/install/launch on toggle. Explicit subsequent workflow action may use original downloads and execute unreviewed code. Off must block subsequent installs/launches, including existing local bundles; no forced termination or removal of installed Steam DLLs is implied. HTTPS/destination/redirect/credential/bounds/path defenses remain mandatory. No telemetry, donation, HTTP bypass or automatic upstream app/runtime updates are restored.

SettingsService exposes IsExecutableWorkflowEnabled(string component), mapping DenuvoFix, BetterSteamTools, OpenSteamTools, LuaToolsPlugin/LuaToolsPluginFrontend, DepotDownloader, Steamless, SteamAutoCrack, CloudRedirect/CloudRedirectAddon. Unknown component false. Settings VM and UI persist eight booleans. Backend agents use settings explicitly; consent is distinct from independently reviewed hash trust. Tests must cover defaults, isolation, disable after enable, enabled success using inert fixtures, and malicious paths/content. Never execute real downloaded binaries in tests.

Ownership: UI/settings agent owns SettingsService, SettingsViewModel, SettingsView.xaml and setting tests. Root owns game-fix consent and documentation. Tool agent owns tool acquisition/preparation, relevant tool services and tests. Integration agent owns plugin/unlocker/injector integration and tests. Shared policy additions must be coordinated before edits.

Implementation verified: native Settings page matches the selected eight-row design using the existing WPF brushes and controls. UI Automation and a window-only screenshot (`../../evidence/executable-settings.png`) confirmed all eight switches off. No real switch was enabled during verification. Full Release suite: 631 passed, zero failed/skipped. Native section-header casing follows the existing app rather than the mockup's uppercase; this is the selected final convention.
